# Baseline profile — Matrix Chat (Chagai fork)
#
# What this file is: a list of classes and methods ART should compile ahead of time when the
# app is installed, instead of interpreting them and JIT-compiling them while the user is
# waiting. AGP merges it into `assets/dexopt/baseline.prof`, and `androidx.profileinstaller`
# (already a dependency, via Compose) writes it to the ART profile on first run.
#
# Why it is written by hand rather than generated: generating one properly means a
# `androidx.baselineprofile` Gradle plugin, a macrobenchmark module and a Play-Services-free
# device to record on — a lot of machinery for a personal build, and it needs the network at
# build time, which this box's capped offline builds do not have. A hand-written profile is the
# documented alternative: it is less precise than a recorded one (it cannot know which *branches*
# are hot) but it covers the right code, and the cost of being approximate is only that a few
# methods are compiled that need not be.
#
# What is already covered without this file: AndroidX and Compose ship their own baseline
# profiles, which AGP merges in (`mergeFdroidReleaseArtProfile`). That is where the ~9 KB profile
# in the APK before this file came from. None of it covers **this app's own** startup path, which
# is what the rules below add.
#
# Syntax (see https://developer.android.com/topic/performance/baselineprofiles):
#   H = "hot"      — called often; compile it
#   S = "startup"  — on the startup path; compile it and keep it warm
#   P = "post-startup"
#   L<class>;      — the class itself, so its <clinit> and field layout are prepared
#   ->**(**)**     — every method, any signature
#
# Ordering is irrelevant; duplicates are harmless.
