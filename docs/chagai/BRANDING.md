# Branding map — every file and string this fork changes

"Matrix Chat" is Element X Android with a different name, icon, application id and default
homeserver. Nothing else about the app is rebranded, and no upstream licence or copyright
header is touched.

The point of this file is that a rebase onto a newer upstream tag is a checklist, not an
archaeology project: these are the only places the brand lives.

---

## 1. The two files that do most of the work

Element X is already parameterised for white-labelling, so almost the whole rebrand is two
constants rather than a sweep through translated strings.

| File | Constant | Was | Now |
|---|---|---|---|
| `plugins/src/main/kotlin/config/BuildTimeConfig.kt` | `APPLICATION_ID` | `io.element.android.x` | `website.chagai.matrixchat` |
| | `APPLICATION_NAME` | `Element X` | `Matrix Chat` |
| | `METADATA_HOST_REVERSED` | `null` | `website.chagai.matrixchat` |
| | `URL_WEBSITE` / `URL_LOGO` / `URL_COPYRIGHT` / `URL_ACCEPTABLE_USE` / `URL_PRIVACY` / `URL_POLICY` | `null` (→ element.io) | `https://chagai.website/matrix-chat/…` |
| `appconfig/src/main/kotlin/io/element/android/appconfig/ApplicationConfig.kt` | `PRODUCTION_APPLICATION_NAME` | `Element` | `Matrix Chat` |
| | `DESKTOP_APPLICATION_NAME` | `Element` | `Matrix Chat` |

**Why that covers every locale.** `app_name` is not a translated string — `app/build.gradle.kts`
generates it per build type with `resValue("string", "app_name", baseAppName)` from
`BuildTimeConfig.APPLICATION_NAME`. Every other user-visible mention of the product is a
`%1$s` placeholder filled at runtime from `BuildMeta.applicationName` (which falls back to
`R.string.app_name`) or from `ApplicationConfig.PRODUCTION_APPLICATION_NAME`. So the launcher
label, the onboarding screens, the notification channel names, the "sign in to…" line, the
analytics prompt, the secure-backup copy and the settings screens all follow from those two
files, in all ~60 shipped locales, with no translation edits at all.

Verified: `grep -ri element libraries/ui-strings/src/main/res/values/` matches only licence
headers — there is no hard-coded "Element" in the English string resources.

## 2. Launcher, monochrome, round and splash icons

The mark is the Matrix `[m]` wordmark: a white `m` between accent-green (`#0DBD8B`) brackets
on a near-black (`#101419`) ground. It is generated from DejaVu Sans Bold outlines and scaled
so the ink sits inside the adaptive-icon safe zone, so no launcher mask can clip it.

| File | What |
|---|---|
| `appicon/element/src/main/res/mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher_foreground.webp` | adaptive foreground |
| `…/ic_launcher_monochrome.webp` | Android 13+ themed icon |
| `…/ic_launcher.webp`, `…/ic_launcher_round.webp` | legacy (pre-API-26) tiles |
| `appicon/element/src/{release,debug,nightly}/res/drawable/ic_launcher_background.xml` | adaptive background colour, per build type (release near-black; debug and nightly tinted so they stay distinguishable) |
| `appicon/element/src/main/ic_launcher-playstore.png` | 512×512 store icon |
| `app/src/main/res/drawable-*dpi/ic_splash_logo.webp` | Android 12+ splash icon, the same mark entirely in accent green so it reads on both the light and dark splash background |
| `app/src/main/res/values{,-night}/themes.xml` | `windowSplashScreenAnimatedIcon` now points at `ic_splash_logo` (upstream shows a transparent, unbranded splash) |

Everything above is regenerated by `tools/chagai/make_icons.py`; re-run it if the mark or the
colours change rather than editing the bitmaps.

## 3. Deep links

| File | Change |
|---|---|
| `libraries/deeplink/impl/.../Constants.kt` | `SCHEME` `elementx` → `matrixchat` |
| `app/src/main/AndroidManifest.xml` | the matching `<data android:scheme="matrixchat">` |
| `libraries/deeplink/impl/src/test/…` and `tools/adb/deeplink.sh` | updated to the new scheme |

The OAuth redirect scheme (`login_redirect_scheme`) is generated from
`METADATA_HOST_REVERSED`, so it became `website.chagai.matrixchat` automatically.

The `https://app.element.io` / `mobile.element.io` app-link filters are deliberately **kept**:
they are harmless (Android only honours them if the matching `assetlinks.json` on those domains
names this app's signature, which it does not), and removing them would mean this build silently
stops handling links the official app handles.

## 4. Attribution (required — Element X is AGPL-3.0)

- `LICENSE`, `LICENSE-COMMERCIAL`, `AUTHORS.md` and every per-file copyright header are
  **unchanged**.
- `features/preferences/impl/.../about/ElementLegal.kt` adds a **Source code (this fork,
  AGPL-3.0)** row to Settings → About, linking to `https://github.com/chagai95/element-x-android`.
  The AGPL requires users of a modified build to be offered its corresponding source; this is
  how that offer is made.
- The string lives in `libraries/ui-strings/src/main/res/values/chagai_fork.xml`, a separate
  file so an upstream translation import never collides with it.
- The download page carries the same notice plus a trademark disclaimer.

## 5. Default homeserver

| File | Change |
|---|---|
| `libraries/matrix/api/.../accountprovider/AccountProvider.kt` | adds `defaultAccountProvider` (`chagai.website`) next to upstream's `matrixOrgAccountProvider` |
| `features/login/impl/.../AccountProviderDataSource.kt` | falls back to `defaultAccountProvider` instead of `matrixOrgAccountProvider` |
| `features/login/impl/.../ConfirmAccountProviderPresenter.kt` | offers `chagai.website` in the suggestion list (matrix.org stays) |

Nothing is forced: "Change account provider" still works, and the provider last actually signed
in to still wins over the default, so only the first run changes. See `FEATURES.md` for the
server-compatibility check behind this.

## 6. Store metadata

`fastlane/metadata/android/en-US/`: `title.txt`, `short_description.txt`,
`full_description.txt`, `images/icon.png`, `images/featureGraphic.png`.

Not changed: `images/phoneScreenshots/*` are still upstream Element X captures. They are only
consumed by store listings, which this build does not have.

## 7. What is deliberately NOT rebranded

- Internal `io.element.android.*` package names, Gradle module names and the
  `ElementXApplication` / `Theme.ElementX` identifiers — invisible to users, and renaming them
  would make every future upstream merge a conflict.
- On-disk datastore names (`elementx_rageshake`, the preference file names, the session store).
  Renaming them would orphan an existing install's data on upgrade.
- The `appicon/element` Gradle module name.
- Upstream's own `tools/release/release.sh` — the fork has its own `release.sh` at the root.
